## 1. Defect Analysis & Root Cause

### The Problem
When a user added a rate item to the Resource Calculator and subsequently clicked "Remove" (`data-costing-remove`), the row either remained stuck in the DOM or subsequent interactions triggered a fatal exception:
```text
Error: Costing line "<lineId>" was not found.
```
Originating in `costing-model.js:find(result.entities.costingLines, text(lineId), "Costing line")`.

### Root Cause
1. **Event Contract Mismatch**:
   - `src/program-planner/js/app.js:publishWorkspaceChange(before, after, command, started)` dispatched `uos:workspace-changed` with `{ detail: record }`.
   - `record` was generated by `UOS.ProgramObservability.recordMutation(...)` containing only `{ revision, command, changed, operations, durationMs }` — **no `workspace` and no `after` property**.
   - `src/program-planner/js/costing.js` listened for `detail.workspace || detail.after`. Because neither property existed, the handler silently returned without updating local state.
2. **Missing Reconciliation on Line Removal**:
   - Unlike `addRate(id)` which employed an ad-hoc `.then(function (saved) { setTimeout(reconcile, 0); })` workaround, `removeCalculatorLine(lineId)` returned `mutate(...)` with **no reconciliation callback, no `.then()` handler, and no DOM re-render**.
   - When line deletion executed, `ProgramApp.updateWorkspace()` removed the line from authoritative storage, but `costing.js` retained its stale local snapshot and DOM rows.
3. **State Divergence & Fatal Lookup**:
   - Because the deleted row remained visible in the DOM, a user clicking remove again (or interacting with the row) passed the removed line ID into `api.removeLine(workspace, lineId)`.
   - The authoritative workspace no longer contained the line ID, throwing `Costing line not found`.

## 2. Remediations Implemented

### 2.1 Canonical Event Payload Contract (`src/program-planner/js/app.js`)
In `publishWorkspaceChange`, unified the event payload into a single authoritative contract:
```javascript
  function publishWorkspaceChange(before, after, command, started) {
    var ended = window.performance && typeof window.performance.now === "function" ? window.performance.now() : Date.now();
    var duration = Math.max(0, ended - started);
    var record = null;
    if (UOS.ProgramObservability && typeof UOS.ProgramObservability.recordMutation === "function") {
      record = UOS.ProgramObservability.recordMutation({
        before: before,
        after: after,
        command: command,
        durationMs: duration
      });
    }
    var detail = {
      workspace: clone(after),
      after: clone(after),
      before: clone(before),
      mutation: record,
      revision: record ? record.revision : (after && after.workspaceRevision) || 0,
      command: command || (record ? record.command : "ProgramApp.updateWorkspace"),
      changed: record ? record.changed : {},
      operations: record ? record.operations : {},
      durationMs: record ? record.durationMs : duration
    };
    document.dispatchEvent(new CustomEvent("uos:workspace-changed", { detail: detail }));
    return record;
  }
```
**Benefits**:
- Delivers the canonical workspace snapshot (`detail.workspace` and `detail.after`) to consumers.
- Retains `detail.mutation` for observability.
- Flattens `revision`, `command`, `changed`, `operations`, and `durationMs` onto `detail` for complete backwards compatibility.

### 2.2 Costing Controller Synchronisation & Preflight (`src/program-planner/js/costing.js`)
1. **Preflight Validation Guard**:
   - `removeCalculatorLine(lineId)` checks both local `state.workspace` and authoritative `ProgramApp.workspace()`.
   - If the line is already absent, it refreshes controller state and exits cleanly without throwing an unhandled exception.
2. **Context & Geometry Lineage Preservation**:
   - For geometry-derived lines, delegates to `WorkAreaService.removeGeometry(workspace, sourceGeometryId)` preserving polygon/job lineage.
   - For manual costing lines, executes `api.removeLine(workspace, lineId)`.
   - Explicitly preserves `workspace.costing = { jobId, section, mode, selectedProjectId }` on the mutated workspace.
3. **Deterministic Post-Mutation Reconciliation**:
   - Chained `.then(function (saved) { reconcile(); return saved; })` ensuring immediate UI update and DOM row removal from canonical `ProgramApp.workspace()`.
4. **Transaction Boundaries & Control Serialisation**:
   - Add/Remove buttons are disabled immediately during in-flight mutations, preventing double-clicks or race conditions.
5. **Event Consumption**:
   - `uos:workspace-changed` and `uos:program-ready` listeners extract `detail.workspace || detail.after`, falling back to `ProgramApp.workspace()` if needed.
   - Guarded `render()` against non-DOM environments (`!root.document`).
   - Exported `removeCalculatorLine` on `ProgramCostingController` for testability.
